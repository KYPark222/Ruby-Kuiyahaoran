# 盤面物理設定

この設定は `app/assets/javascripts/pachinko_physics_config.js` に集約しています。盤面形状と摩擦・反発はPNG/SVGの見た目に合わせた仮初期値ですが、重力と発射速度は玉径を基準に実スケールへ換算しています。

## 座標と初期値

- 物理座標とオーバーレイSVGは `viewBox="0 0 1015 1550"` を共有します。盤面PNGも1015×1550pxです。盤面アートのソースSVGは800×1120ですが、現在の表示アートはPNGなので物理座標はPNG/オーバーレイ基準です。
- 玉半径8、釘衝突半径6、通常レール幅8、液晶ガード幅7（盤面座標単位）。釘と左上返し用の釘4本のID・座標・表示半径・種別は `app/assets/data/pachinko-board-layout.json` に集約し、表示SVGと物理演算の双方で同じ中心を使います。ヘソ開口を塞いでいた下部釘 `lower-1-7` / `lower-1-8` は削除済みです。
- 重力、反発、摩擦、速度上限、固定時間ステップ、16分割のサブステップ、Matter.js反復回数は設定モジュールで調整します。
- 発射点は左下の `(145, 1280)`。角度は画面座標系で `-101.31°`、弱・中・強の初速はそれぞれ99.7、115.6、128.4（px/step）です。発射点を右へ寄せると近傍の既存釘に衝突して初動が止まるため、左下の通路位置を維持します。
- 重力は実スケールに合わせています。パチンコ玉の直径11mmを表示半径8pxに対応させると1px≒0.6875mm（1.4545px/mm）となり、実重力9.80665m/s²は約14,264px/s²です。Matter.jsの有効加速度は `gravity.scale × 10^6 px/s²` なので `scale=0.01426` とします。初速も同じ時間スケール（約7.55倍）で換算しており、中打ちは約4.76m/sで実機の4〜6m/sに相当します。高速化に伴い `timing.subSteps=16`、`capacity.maxSpeed=136` とし、1サブステップあたりの移動量を従来と同程度に保って衝突判定を安定させています。
- 開口許容幅、摩擦・反発、盤面形状は見た目・動作確認用の仮設定です。実機計測値ではありません。
- 左側の落下通路 `left-flow-lane-outer` / `left-flow-lane-inner` は見た目のみで、物理レールとしては使いません。以前は通路の両端を物理レールにしていましたが、玉が詰まるため衝突体を外しました。
- ヘソ開口の左右には `entry.guideWalls` の物理ガイドを置き、入口幅を玉半径込みで確保します。ガイド位置は開口楕円から算出し、表示位置と独立した固定軌道は与えません。さらに `entry.funnelWalls` の隠しファネル（左右1本ずつ、厚さ6、摩擦0.01）をガイド上端まで伸ばし、自然流下でヘソへ入る経路を作ります。
- 添付の座標ガイド（960×1920）に示された返し釘 N101〜N104 は、盤面座標へ X=1015/960、Y=1550/1920 で変換してJSONに保持します。N104は左通路への抜けを優先して換算位置から小幅に補正しています。返しレールは R002（上部給球レール）と R003（その下側境界）のみを物理レールとして残し、左側ガイド R001 と下降ガイド R004 は発射レーンを塞ぐため削除しました。R002/R003は厚さ6、摩擦0です。返し釘は衝突検証用に反発係数0.95、摩擦0にしています。これらは実機計測値ではなく、添付図に合わせた調整値です。
- 液晶外周の `lcd-top-guard` / `lcd-left-guard` / `lcd-right-guard` / `lcd-bottom-guard` は見た目のみ（`data-physics-disabled="true"`）です。物理境界にすると玉が液晶まわりで滞留したため、実機と同じく液晶の手前を玉が落ちる扱いにしました。

## 発射と物理設定の上書き

`PachinkoPhysicsConfig.values`を初期設定として使います。盤面ごとの上書きは `PachinkoPhysics.createSimulation({ ..., options })` に渡せます。発射時は `simulation.launchBall({ strength: "weak" | "medium" | "strong" })` を使います。発射方向と速度は生成時に一度設定し、その後の位置はMatter.jsが更新します。

## 入賞率の試行統計

具体的な目標入賞率は未指定なので初期値は `null` です。画面の「物理検証・入賞率」欄から入力・変更できます。稼働中のsimulationでは `simulation.stats.setTargetRate(目標パーセント)` を呼び、`simulation.stats.snapshot()`から目標値、完了試行数、入賞数、排出数、保留数、実測率、目標差、発射強度別結果、各試行のパラメータと時刻を取得できます。設定を解除するときは `setTargetRate(null)` を使います。集計はページ内メモリのみで、永続化しません。

実測率の分母は結果が確定した試行（入賞または盤面外への排出）のみです。流下中は保留に含まれ、手動削除はキャンセル扱いで分母から除外します。物理パラメータや玉の位置を確率で補正する処理はありません。
ページ表示時にデモ玉は自動発射しません。ゲーム発射玉は `simulation.launchBall({ kind: "game", strength: "weak" | "medium" | "strong" })` で登録します。

## 入賞とゲーム進行

ヘソ開口はSVGの `[data-physics-role='entry-sensor']` 楕円（座標 `(508, 1194)`、半径 `rx=23, ry=13`）を参照します。玉の中心が開口範囲を下向きに通過した時だけ入賞し、物理ワールドから玉を削除します。時間経過でヘソへ移動させるフォールバック（旧 `entry.fallbackSteps`）は削除済みで、入賞は必ず物理挙動で到達した場合に限ります。低速で滞留した玉は `capacity.stallSpeed` / `capacity.stallSteps`（既定0.2px/フレーム・1920サブステップ＝約2秒）で盤面外排出として回収します。

ブラウザから `POST /pachinko/entry` に玉IDを送り、Ruby側でセッション保留を更新して抽選します。玉IDは処理済みリストと照合し、重複入賞を拒否します。保留は4個までで、満タン時は抽選・追加を行いません。抽選率は現状の仮設定で1/319です。保留数はページ再読込後もセッションに保持し、リセット操作で消去します。発射強度ボタンは弱・中・強それぞれ1球を発射します。

## デバッグ

開発用の衝突形状、釘円、ヘソ判定楕円、発射ベクトル、玉の速度ベクトルと状態を表示するには、URLに `?physicsDebug=1` を付けます。またはConsoleから `PachinkoPhysics.get(document.querySelector("[data-board-scene]")).setDebug(true)` を呼びます。通常表示では物理形状を重ねません。

## 未校正の箇所

PNGには部品の正確な深度や裏側形状がなく、液晶外周ガードや左側通路は見た目のみの近似です。釘の傾斜・高さの3D効果と実機に近いヘソ到達頻度は未校正です。重力と発射速度は玉径基準の実スケールですが、隠しファネルの形状と摩擦・反発は、弱・中・強で自然入賞が偏らないよう調整した仮値であり、実機の物理到達率を示すものではありません。
