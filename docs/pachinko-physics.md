# 盤面物理設定

この設定は `app/assets/javascripts/pachinko_physics_config.js` に集約し、盤面形状は `app/assets/data/pachinko-board-layout.json` に保持しています。盤面形状と摩擦・反発はPNG/SVGの見た目に合わせた仮初期値ですが、重力と発射速度は玉径を基準に実スケールへ換算しています。

## 座標と初期値

- 物理座標とオーバーレイSVGは `viewBox="0 0 1015 1550"` を共有します。盤面PNGも1015×1550pxです。盤面アートのソースSVGは800×1120ですが、現在の表示アートはPNGなので物理座標はPNG/オーバーレイ基準です。
- 玉半径8、釘衝突半径6、通常レール幅8、液晶ガード幅7（盤面座標単位）。釘と左上返し用の釘4本のID・座標・表示半径・種別は `app/assets/data/pachinko-board-layout.json` に集約し、表示SVGと物理演算の双方で同じ中心を使います。ヘソ開口を塞いでいた下部釘 `lower-1-7` / `lower-1-8` は削除済みです。
- 重力、反発、摩擦、速度上限、固定時間ステップ、6分割のサブステップ、Matter.js反復回数は設定モジュールで調整します。
- 打ち出し位置は左右とも左下 `(145, 1280)`・角度 `-101.31°` で共通です。打法の違いは初速だけで、左打ち30・右打ち36（px/step）です。右打ちは強い初速で上部ステージを横切り、盤面右側へ落ちます。左右で盤面形状は同一です。以前は右打ち用に右下 `(870, 1280)` から発射していましたが、打ち出し位置を左下に統一しました。右打ち用の隠し物理レール `right-board-boundary` は、右へ流れた玉を右下へ案内するために残しています。
- 重力と発射速度は玉径基準の実スケールから換算しています。パチンコ玉の直径11mmを表示半径8pxに対応させると1px≒0.6875mm（1.4545px/mm）となり、実重力9.80665m/s²は約14,264px/s²です。Matter.jsの有効加速度は `gravity.scale × 10^6 px/s²` なので、実時間なら `scale=0.01426`、初速は左打ち約3.7m/s・右打ち約4.5m/sになります。ただし実時間では演出として速すぎるため、**時間スケールを1/3（3倍スロー）**にし、重力は1/9の `0.001585`、初速は左打ち30（約1.2m/s）・右打ち36（約1.5m/s）としています。`timing.subSteps=6`、`capacity.maxSpeed=46` は、1サブステップあたりの移動量を抑えて衝突判定を安定させるための値です。
- 開口許容幅、摩擦・反発、盤面形状は見た目・動作確認用の仮設定です。実機計測値ではありません。
- 左側の落下通路 `left-flow-lane-outer` / `left-flow-lane-inner` は見た目のみで、物理レールとしては使いません。発射レーンと盤面を分ける `left-outer-rail` は物理レールとして有効にし、発射玉が上部で盤面へ入ったあと、液晶左側を流れる玉が発射レーンへ落ちないようにしています。
- ヘソ開口の左右には `entry.guideWalls` の物理ガイドを置き、入口幅を玉半径込みで確保します。ガイド位置は開口楕円から算出し、表示位置と独立した固定軌道は与えません。さらに `entry.funnelWalls` の隠しファネル（左右1本ずつ、厚さ6、摩擦0.01）をガイド上端まで伸ばし、自然流下でヘソへ入る経路を作ります。
- 添付の座標ガイド（960×1920）に示された返し釘 N101〜N104 は、盤面座標へ X=1015/960、Y=1550/1920 で変換してJSONに保持します。N104は左通路への抜けを優先して換算位置から小幅に補正しています。返しレールは R002（上部給球レール）と R003（その下側境界）のみを物理レールとして残し、左側ガイド R001 と下降ガイド R004 は発射レーンを塞ぐため削除しました。R002/R003は厚さ6、摩擦0です。返し釘は衝突検証用に反発係数0.95、摩擦0にしています。これらは実機計測値ではなく、添付図に合わせた調整値です。
- 液晶外周の `lcd-top-guard` / `lcd-left-guard` / `lcd-right-guard` / `lcd-bottom-guard` は装飾用で、物理は無効（`data-physics-disabled="true"`）のままです。代わりに `pachinko-board-layout.json` の `lcdProtection.collider` を閉じた隠しコライダー（厚さ7、摩擦0.005）として配置し、液晶表示範囲へ玉が入らないようにしました。上面は中央を頂点にした浅い屋根、下面は表示範囲の下端に合わせています。液晶の左右下端からは `lcdProtection.sideGuides` の短いガイドで玉を下部釘領域へ戻し、既存のヘソファネルで自然入賞させます。`left-outer-rail` を有効にしているのは、液晶左側を流れる玉を発射レーンから分離するためです。
- 液晶屋根の直上にあった釘列 `upper-3-*`（y=320、9本）は盤面アートには描かれておらず、SVGの物理釘だけが右ルートを塞いでいました。屋根上面 y≈344.5 と釘下端 y=327 の隙間が実質1.5pxしかなく、右打ちの玉が上部ステージを横切れなかったため、この9本を `pachinko-board-layout.json` から削除しました（ピン総数89→80）。

## 発射と物理設定の上書き

`PachinkoPhysicsConfig.values`を初期設定として使います。盤面ごとの上書きは `PachinkoPhysics.createSimulation({ ..., options })` に渡せます。発射時は `simulation.launchBall({ kind: "game", mode: "left" | "right" })` を使います。発射方向と速度は生成時に一度設定し、その後の位置はMatter.jsが更新します。任意の位置・速度で検証したい場合は `launchBall({ kind, x, y, velocity })` も使えます。

## 入賞率の試行統計

具体的な目標入賞率は未指定なので初期値は `null` です。画面の「物理検証・入賞率」欄から入力・変更できます。稼働中のsimulationでは `simulation.stats.setTargetRate(目標パーセント)` を呼び、`simulation.stats.snapshot()`から目標値、完了試行数、入賞数、排出数、保留数、実測率、目標差、打ち出し別結果、各試行のパラメータと時刻を取得できます。設定を解除するときは `setTargetRate(null)` を使います。集計はページ内メモリのみで、永続化しません。

実測率の分母は結果が確定した試行（入賞または盤面外への排出）のみです。流下中は保留に含まれ、手動削除はキャンセル扱いで分母から除外します。物理パラメータや玉の位置を確率で補正する処理はありません。
ページ表示時から `autoLaunch` 設定（既定1秒間隔、同時10球まで、角度±0.2°）で自動発射します。同時数の上限は、1秒間隔でも発射を間引かないために、流下中の玉数（実測最大10球）に合わせています。`simulation.isRunning` が false のとき（打ち出し停止・一時停止中）、または同時玉数が上限のときは発射しません。ゲーム発射玉は `simulation.launchBall({ kind: "game", mode: "left" | "right", velocity })` で登録します。自動発射は角度だけを微小に揺らし、打法は直近に選んだ「左打ち」「右打ち」ボタンの値を使います。角度ジッターを±0.2°まで小さくしているのは、右打ちの軌道が上部ステージで大きく乱高下しないようにするためです。実測（各200球、角度ジッター±0.2°）では左打ちが46%でヘソ入賞し、右打ちは12%にとどまります。右打ちの玉は上部ステージから右へ流れ、`right-board-boundary` を伝って右下へ排出されやすいためで、実機の「右打ちは右へ流れやすい」挙動として許容しています。

## 入賞とゲーム進行

ヘソ開口はSVGの `[data-physics-role='entry-sensor']` 楕円（座標 `(508, 1194)`、半径 `rx=23, ry=13`）を参照します。玉の中心が開口範囲を下向きに通過した時だけ入賞し、物理ワールドから玉を削除します。時間経過でヘソへ移動させるフォールバック（旧 `entry.fallbackSteps`）は削除済みで、入賞は必ず物理挙動で到達した場合に限ります。低速で滞留した玉は `capacity.stallSpeed` / `capacity.stallSteps`（既定0.2px/フレーム・720サブステップ＝約2秒）で盤面外排出として回収します。

ブラウザから `POST /pachinko/entry` に玉IDを送ると、Ruby側でセッション保留を1個加算します。玉IDは処理済みリストと照合し、重複入賞を拒否します。保留は4個までで、満タン時は追加しません。そのあとクライアントが `POST /pachinko/consume` を呼び、保留を1個消費して抽選結果（`jackpot` / `miss`）を受け取ります。抽選率は現状の仮設定で1/319です。保留が残っている間は消費と抽選を繰り返し、ページ再読込後に残った保留も起動時に消費します。リセット操作で保留と処理済み玉IDを消去します。

抽選時は液晶の3桁リール（`#symbol-reels`）を回転させ、左・中・右の順に停止します。大当たりでは3桁を揃えて「大当たり」、はずれでは揃わない数字で「抽選：はずれ」を表示します。回転中は `#lcd-interface[data-lcd-state="spinning"]`、結果表示は `jackpot` / `miss` になります。「左打ち」「右打ち」ボタンはそれぞれの打法で1球を手動発射し、同時に自動発射の打法も切り替えます。

## デバッグ

開発用の衝突形状、釘円、ヘソ判定楕円、発射ベクトル、玉の速度ベクトルと状態を表示するには、URLに `?physicsDebug=1` を付けます。またはConsoleから `PachinkoPhysics.get(document.querySelector("[data-board-scene]")).setDebug(true)` を呼びます。通常表示では物理形状を重ねません。

## 未校正の箇所

PNGには部品の正確な深度や裏側形状がなく、液晶外周の装飾ガードや左側通路は見た目のみの近似です。液晶コライダーとサイドガイドは表示範囲を避ける形状にしていますが、実機の役物形状の再現ではありません。釘の傾斜・高さの3D効果と実機に近いヘソ到達頻度は未校正です。重力と発射速度は玉径基準の実スケールを1/3スローにした値ですが、液晶コライダー、サイドガイド、隠しファネルの形状と摩擦・反発は、左右の打法差が自然に出るよう調整した仮値であり、実機の物理到達率を示すものではありません。
